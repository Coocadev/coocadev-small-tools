# MailSkin implementation and acceptance plan — 0.2.0

Date: 2026-10-15. Original demand: https://www.reddit.com/r/Wordpress/comments/1ihazwd/how_to_style_emails_sent_via_wordpress/ . WP HTML Mail is an established direct alternative; this compact branding layer makes no uniqueness claim. Current name/slug and product-page review remain publication gates.

MVP: explicit opt-in, three fixed HTML-fragment skins, site brand, strict six-digit hex color, editable local-media image ID, plain signature, saved no-send sandboxed preview. `wp_mail` body only changes: recipients/subject/headers/attachments preserved; text/plain remains plain; multipart bypassed; explicit HTML wrapped or inserted into an existing complete document without nesting another document. Complete documents retain their original outer skin. `ccms_should_brand` can skip selected mail. No SMTP control, delivery guarantee, analytics or mail log.

Storage: one non-autoloaded `ccms_settings` option. Save requires POST, administrator capability and nonce, then full scalar/enum/color/logo validation before writing. Escaped brand/signature, constrained CSS; original trusted mail HTML preserved. Preview is escaped srcdoc with sandbox and never invokes mail. No outgoing HTTP API; a configured logo is a normal site-media image requested by the recipient application. Deactivation stops branding; uninstall preserves settings unless deletion selected. Single-site lifecycle; no network cleanup claim.

Review crosswalk: R01/R02 naming/page OPEN; R03/G01 full GPL source/no gates; R04/R08 fixed email-safe CSS with hex validation, no frontend bundles; R05/R06 protected controller and typed scalar schema; R07 output-context escaping including preview; R09/G02 no tracking/external APIs; R10 no buffers; R11–R13 native options/attachment/admin URLs, no executable writes; R14 unique prefix; R15 native APIs/no custom SQL; R16–R18 exact version and package evidence. G03–G06 no unsolicited credits, advertising or false guarantees. L01 malformed checkbox; L06 real-directory/exact-ZIP install. L03–L05 and later Avalon lessons have no analogous custom sessions, media finalize, row AJAX or network data architecture here.

Acceptance: disabled default, all three skins, HTML fragment/full-document preservation, plaintext output, identical headers/recipients/attachments, idempotence, multipart bypass, preview without mail, per-message opt-out, CSS/XSS/malformed checkbox and invalid logo. Then actual HTTP capability/nonce/invalid scalar tests, debug log, lifecycle, min/current WP/PHP, final ZIP and real email-client/third-party template review. State only observed outcomes PASS; preview is not inbox rendering evidence.
