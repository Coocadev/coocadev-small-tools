# HoursGo implementation and acceptance plan — 0.2.0

Date: 2026-10-15. Original demand signal: https://wordpress.org/support/topic/holiday-hours-2/ . Narrow difference: quick temporary operating-hour messages with automatic return to the usual seven-day schedule; no appointment/directory suite. Names/slug require current clearance before publishing.

MVP: one business/location, one interval per weekday, blank day closed; 12 non-overlapping plain-text exception messages; maximum31-day intervals within next year; shortcode `[cchg_hours]`. No overnight/split periods or structured-data claims. Site-local dates convert to UTC with exact round-trip validation; missing/repeated DST minutes are rejected. Effective state uses one server timestamp, start-inclusive/end-exclusive. No cron is required. Existing browser tabs recalculate on refresh. Weekly schedule follows timezone changes; exception instants remain UTC.

Storage: non-autoloaded `cchg_settings` option only. POST+`manage_options`+nonce before allowlisted grid parsing, scalar validation and one atomic settings write. All output escaped. No user data, assets, remote APIs or cookies. Shortcode sends no-cache signals; operators must exclude external page/CDN caching. Deactivation preserves settings; uninstall deletes only after explicit opt-in. Network-wide uninstall is outside the single-site release claim.

Review map: R01/R02 branding/product page OPEN; R03/G01 GPL/no local gates; R04/R08 no arbitrary JS/CSS; R05/R06 method/capability/nonce+complete schema before write; R07 escaping; R09/G02 no remote/telemetry; R10 no buffers; R11–R13 WordPress URLs/options, no executable writes; R14 unique namespace/prefix; R15 native option API; R16–R18 exact-version and package evidence. G03–G06 no ads/false guarantees. L01 checkbox shape; L06 real-directory install; L03–L05 no custom transactional writer, AJAX-row adapter or network cleanup claim. Avalon-specific later lessons are evaluated only where applicable.

Acceptance: seven days, closed blank day, open/close boundaries, server timezone/day consistency, exact exception bounds, automatic expiry, invalid calendar date, DST gap/repeated hour, overlap, duration/count limits, malformed checkbox, inverted hours, safe display/cache flags. Then HTTP malformed fields/nonce/capability, lifecycle preserve/delete, debug log, min/current WP/PHP, real cache exclusion and keyboard/mobile/RTL/screen-reader. Record actual PASS/OPEN outcomes per release, not the existence of this plan.
