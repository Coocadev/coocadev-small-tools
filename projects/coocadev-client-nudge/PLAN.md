# Client Nudge implementation and acceptance plan — 0.2.0

Date: 2026-10-15. Original demand signal: https://wordpress.org/support/topic/suggestion-345/ . Unlike broad project managers, this MVP focuses on requesting client materials with private tasks and one optional incomplete-only weekly reminder. Names/slugs remain subject to current directory/brand clearance.

Deliver a private administrator-created task with assignee account ID, plain title/instructions and real due date; an owned-task completion board; recipient-only consent/opt-out; 50-item pagination; bounded cron with atomic per-week deduplication; standard privacy export/erase; opt-in uninstall cleanup. Registered users only. No marketing campaigns, attachments, external APIs, payment or licence gates. Code is GPL-2.0-or-later with full English-readable source/comments and no build prerequisite.

Data/access map: `cccn_task` private posts plus assignee/due/done metadata; `cccn_optin_<blogID>` recipient metadata; non-autoloaded weekly claim/cursor options. Administrator creation/deletion requires `manage_options`; completion verifies concrete assignment; consent derives the actor ID from the session. POST+nonce precede mutations. Scalar payloads reject arrays/markup; calendar round-trip rejects impossible dates. No private content in public REST/search. Cache exclusion for authenticated board pages is mandatory at an external page/CDN cache.

Lifecycle: activation schedules future cron without email; deactivation clears cron and retains data; opt-in deletion on uninstall removes only current-site plugin data. Privacy exporter batches per owner; eraser deletes page one repeatedly to avoid skipping rows after deletion. User deletion cleans the currently loaded site. Network activation/universal network cleanup are outside supported scope. Weekly claim is persisted before mail to avoid duplicates on transport ambiguity; crash may skip one week, mail acceptance is not delivery. Claim retention is eight days with bounded purge.

Shared review crosswalk: R01/R02 naming/ownership OPEN; R03/G01 GPL full source/no gates implemented; R04/R08 no frontend assets/arbitrary CSS; R05/R06 nonce, object access, typed field boundaries; R07 late escaping; R09/G02 no telemetry/external runtime APIs; R10 no buffers; R11/R12/R13 no executable writes and WordPress paths/URLs; R14 namespace/prefix; R15 narrow prepared claim cleanup SQL; R16–R18 exact-version/minimum/current/package evidence required. G03–G06 no unwanted branding/ads or absolute guarantees. L01 strict checkbox; L03 atomic deduplication; L05 site-specific consent and explicit network limits; L06 clean directory/ZIP and separate-process uninstall. L04 and Avalon-specific L07–L09 do not imply this product has those adapters or custom sessions.

Acceptance: test successful create/own completion, stranger denial, client create denial, no initial mail, opt-in/out, pending-only body, same-week deduplication, next week, privacy isolation/export/erase, anonymous board, invalid date, malformed fields and unchanged persisted state. Add current/minimum WP/PHP, actual HTTP nonce/capability/type checks, debug log, lifecycle preserve/delete, no external requests, keyboard/mobile/RTL/screen-reader and exact ZIP smoke. Only observed checks are PASS in the release report; directory approval, real-inbox delivery and network-wide lifecycle are not claimed.
